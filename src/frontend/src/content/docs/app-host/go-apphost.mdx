A Go AppHost is a Go program that defines the resources in your application and how they connect. It uses the same app model as a C# AppHost, through a Go SDK that the Aspire CLI generates from the hosting integrations you install.

## Prerequisites

- [Go](https://go.dev/dl/) 1.26 or later, with `go` on your `PATH`
- The [Aspire CLI](/get-started/install-cli/)
- A container runtime for the Redis container in the starter template. See [Aspire prerequisites](/get-started/prerequisites/) for the supported options.

## Create a Go AppHost

Create a new app from the Go starter template:

```bash title="Aspire CLI"
aspire new aspire-go-starter -n aspire-app -o aspire-app
```

The template creates a Go AppHost, a Go API that uses a Redis cache, and the generated SDK. To choose from the templates that support Go, run `aspire new --language go` instead.

<LearnMore>
  See the [`aspire new` command reference](/reference/cli/commands/aspire-new/) for all options.
</LearnMore>

The project has the following structure:

<FileTree>

- aspire-app/
  - .aspire/modules/  Generated Go SDK (do not edit)
    - aspire.go
    - base.go
    - go.mod
    - transport.go
  - .vscode/
    - extensions.json  Recommended VS Code extensions
  - api/  Go API that the AppHost runs
    - go.mod
    - main.go
    - telemetry.go
  - .gitignore  Keeps the generated .aspire/ directory out of source control
  - apphost.go  Your AppHost entry point
  - aspire.config.json  Aspire configuration
  - go.mod  Go module for the AppHost

</FileTree>

## Run the AppHost

From the project directory, start the AppHost with the Aspire CLI:

```bash title="Aspire CLI"
aspire run
```

The CLI regenerates the SDK when the `packages` list has changed, starts the AppHost with `go run .`, and prints the dashboard URL. Open the dashboard to see the `cache` and `api` resources with their logs, traces, and metrics.

:::note
Always start the AppHost with `aspire run`. The CLI sets the environment variables that the SDK uses to connect to the AppHost server, so running `go run .` on its own fails with `REMOTE_APP_HOST_SOCKET_PATH environment variable not set`.
:::

## apphost.go

The AppHost is a `package main` Go program. The starter template defines a Redis cache and a Go API that references it:

```go title="apphost.go"
package main

import (
	"log"

	"apphost/modules/aspire"
)

func main() {
	builder, err := aspire.CreateBuilder()
	if err != nil {
		log.Fatal(aspire.FormatError(err))
	}

	// A Redis cache the API will use for read-through caching.
	cache := builder.AddRedis("cache")

	// The Go HTTP API. WithModTidy runs "go mod tidy" before launching so that
	// go.sum is always up to date. Aspire injects:
	//   - "ConnectionStrings__cache" so the API can dial Redis.
	//   - "OTEL_EXPORTER_OTLP_*" env vars (via WithOtlpExporter) so traces,
	//     metrics, and logs flow to the Aspire dashboard.
	api := builder.AddGoApp("api", "./api").
		WithModTidy().
		WithReference(cache).
		WaitFor(cache).
		WithHttpEndpoint(&aspire.WithHttpEndpointOptions{Env: aspire.StringPtr("PORT")}).
		WithExternalHttpEndpoints().
		WithOtlpExporter()

	// Each call records its failure on the handle that it returns, so check every resource.
	for _, resource := range []aspire.Resource{cache, api} {
		if err := resource.Err(); err != nil {
			log.Fatal(aspire.FormatError(err))
		}
	}

	app, err := builder.Build()
	if err != nil {
		log.Fatal(aspire.FormatError(err))
	}
	if err := app.Run(); err != nil {
		log.Fatal(aspire.FormatError(err))
	}
}
```

The program has three parts:

1. `aspire.CreateBuilder()` connects to the AppHost server that the CLI starts and returns the builder.
2. `AddRedis` and `AddGoApp` add resources. Each call returns a handle, so `WithReference`, `WaitFor`, and the other configuration methods chain onto it.
3. A loop checks the handle of each resource with `Err()`, because a failed call records its error on the handle that it returns, not on the builder. `builder.Build()` creates the application, and `app.Run()` blocks until the AppHost stops. Both return an error. See [Go AppHost API conventions](/app-host/go-apphost-conventions/#errors) for how to check handles and format errors.

## aspire.config.json

The `aspire.config.json` file is the central configuration for your AppHost:

```json title="aspire.config.json"
{
  "appHost": {
    "path": "apphost.go",
    "language": "go"
  },
  "packages": {
    "Aspire.Hosting.Go": "%ASPIRE_VERSION%",
    "Aspire.Hosting.Redis": "%ASPIRE_VERSION%"
  },
  "profiles": {
    "https": {
      "applicationUrl": "https://localhost:17127;http://localhost:15118",
      "environmentVariables": {
        "ASPIRE_DASHBOARD_OTLP_ENDPOINT_URL": "https://localhost:21169",
        "ASPIRE_RESOURCE_SERVICE_ENDPOINT_URL": "https://localhost:22260"
      }
    },
    "http": {
      "applicationUrl": "http://localhost:15118",
      "environmentVariables": {
        "ASPIRE_DASHBOARD_OTLP_ENDPOINT_URL": "http://localhost:19001",
        "ASPIRE_RESOURCE_SERVICE_ENDPOINT_URL": "http://localhost:20115",
        "ASPIRE_ALLOW_UNSECURED_TRANSPORT": "true"
      }
    }
  }
}
```

### Key sections

| Section | Description |
|---------|-------------|
| `appHost.path` | Path to the AppHost entry point (`apphost.go`) |
| `appHost.language` | The AppHost language (`go`) |
| `packages` | Hosting integration packages and their versions. `aspire add` updates this section. |
| `profiles` | Launch profiles with dashboard URLs and environment variables |

## Generated SDK

The `.aspire/modules/` directory holds the Go SDK that the CLI generates from the packages in `aspire.config.json`. The CLI creates and updates it, so don't edit these files.

| File | Purpose |
|------|---------|
| `aspire.go` | Typed API for the installed integrations |
| `base.go` | Handle, option, and error infrastructure |
| `transport.go` | JSON-RPC transport to the AppHost server |

The SDK is one Go package for all integrations. The AppHost's `go.mod` file maps the `apphost/modules/aspire` import path to the `.aspire/modules/` directory, so `apphost.go` imports it like any other package:

```text title="go.mod"
module apphost

go 1.26

require apphost/modules/aspire v0.0.0

replace apphost/modules/aspire => ./.aspire/modules
```

The SDK regenerates when:

- You run `aspire add` to add or update an integration
- You run `aspire run` or `aspire start` and the package list has changed
- You run `aspire restore`

:::tip
The starter's `.gitignore` already lists `.aspire/`. The directory holds generated files that the CLI recreates from `aspire.config.json`, so keep it out of source control.
:::

### Restore the SDK

Run `aspire restore` to regenerate the SDK without starting the AppHost:

```bash title="Aspire CLI"
aspire restore --apphost apphost.go
```

Restore after you clone a repository, switch branches, or edit the `packages` section by hand. In CI, restore before any step that compiles the AppHost, such as `go build` or `go vet`.

## Add integrations

Use `aspire add` from the AppHost directory to add a hosting integration. The CLI adds the package to `aspire.config.json` and regenerates the Go SDK in `.aspire/modules/`:

```bash title="Aspire CLI"
aspire add postgresql
```

The `packages` section now lists the PostgreSQL integration:

```json title="aspire.config.json" ins={5}
{
  "packages": {
    "Aspire.Hosting.Go": "%ASPIRE_VERSION%",
    "Aspire.Hosting.Redis": "%ASPIRE_VERSION%",
    "Aspire.Hosting.PostgreSQL": "%ASPIRE_VERSION%"
  }
}
```

The regenerated SDK has an `AddPostgres` method. This AppHost adds a PostgreSQL server with one database and gives the API access to it:

```go title="apphost.go"
package main

import (
	"log"

	"apphost/modules/aspire"
)

func main() {
	builder, err := aspire.CreateBuilder()
	if err != nil {
		log.Fatal(aspire.FormatError(err))
	}

	cache := builder.AddRedis("cache")
	db := builder.AddPostgres("postgres").AddDatabase("postgresdb")

	api := builder.AddGoApp("api", "./api").
		WithModTidy().
		WithReference(cache).
		WithReference(db).
		WaitFor(cache).
		WaitFor(db).
		WithHttpEndpoint(&aspire.WithHttpEndpointOptions{Env: aspire.StringPtr("PORT")}).
		WithExternalHttpEndpoints().
		WithOtlpExporter()

	// Each call records its failure on the handle that it returns, so check every resource.
	for _, resource := range []aspire.Resource{cache, db, api} {
		if err := resource.Err(); err != nil {
			log.Fatal(aspire.FormatError(err))
		}
	}

	app, err := builder.Build()
	if err != nil {
		log.Fatal(aspire.FormatError(err))
	}
	if err := app.Run(); err != nil {
		log.Fatal(aspire.FormatError(err))
	}
}
```

- `AddPostgres` adds the PostgreSQL server, and `AddDatabase` returns a handle for a database on that server.
- `WithReference(db)` passes the connection details to the API as environment variables named after the resource, such as `POSTGRESDB_URI`. See [Connect to PostgreSQL](/integrations/databases/postgres/postgres-connect/) for a Go example that reads them.
- `WaitFor(db)` starts the API after the database is ready.
- The loop checks each handle with `Err()` before `Build`, because a failed call records its error on the handle that it returns.

## Orchestrate apps in other languages

A Go AppHost can run resources written in other languages next to your Go apps. Add the integration for each language that you use. Python and Node.js must also be installed, because these resources run on your machine:

```bash title="Aspire CLI"
aspire add python
aspire add javascript
```

This AppHost runs a Go API and a Python recommendation service that share a Redis cache, and a Vite frontend that calls both:

```go title="apphost.go"
package main

import (
	"log"

	"apphost/modules/aspire"
)

func main() {
	builder, err := aspire.CreateBuilder()
	if err != nil {
		log.Fatal(aspire.FormatError(err))
	}

	cache := builder.AddRedis("cache")

	api := builder.AddGoApp("api", "./api").
		WithReference(cache).
		WaitFor(cache).
		WithHttpEndpoint(&aspire.WithHttpEndpointOptions{Env: aspire.StringPtr("PORT")})

	recommender := builder.AddUvicornApp("recommender", "./recommender", "main:app").
		WithReference(cache).
		WaitFor(cache)

	web := builder.AddViteApp("web", "./web").
		WithReference(api).
		WithReference(recommender).
		WaitFor(api)

	for _, resource := range []aspire.Resource{cache, api, recommender, web} {
		if err := resource.Err(); err != nil {
			log.Fatal(aspire.FormatError(err))
		}
	}

	app, err := builder.Build()
	if err != nil {
		log.Fatal(aspire.FormatError(err))
	}
	if err := app.Run(); err != nil {
		log.Fatal(aspire.FormatError(err))
	}
}
```

- `AddUvicornApp` runs a Python ASGI app. The `main:app` argument names the Python module and the application object in it.
- `AddViteApp` runs a Vite frontend. `AddUvicornApp` and `AddViteApp` already register an `http` endpoint that reads its port from `PORT`, so only the Go API calls `WithHttpEndpoint`.
- `WithReference` and `WaitFor` work the same for every resource type. The frontend receives the endpoints of the API and the recommender, and it starts after the API is ready.
