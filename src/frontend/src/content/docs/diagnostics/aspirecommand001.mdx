`ASPIRECOMMAND001` was emitted by Aspire 13.2 and later releases when code used the required-command validation APIs while they were experimental. This diagnostic no longer applies in Aspire 17.0 and later because custom required-command validation is stable.

The following APIs are no longer experimental:

- The <ApiReference name="Aspire.Hosting.RequiredCommandResourceExtensions.WithRequiredCommand" /> overload that accepts a validation callback (`Func<RequiredCommandValidationContext, Task<RequiredCommandValidationResult>>`)
- `RequiredCommandAnnotation`
- `IRequiredCommandValidator`
- `RequiredCommandValidationContext` and `RequiredCommandValidationResult`

## Validation is advisory

Required-command validation is annotation-driven and runs at run time against the app model. Validation is advisory: when a command is missing, or a validation callback returns a failure, Aspire logs a warning and the resource still attempts to start. Validation doesn't block startup.

```csharp title="AppHost.cs"
var builder = DistributedApplication.CreateBuilder(args);

builder.AddExecutable("worker", "my-tool", ".")
    .WithRequiredCommand("my-tool", context =>
        Task.FromResult(context.Success()));

builder.Build().Run();
```

A callback can return `context.Failure("Install a supported tool version.")` to report a warning with a custom message.

## If you still see this warning

Upgrade the Aspire CLI, AppHost SDK, and hosting integration packages to Aspire 17.0 or later. After upgrading, remove any `ASPIRECOMMAND001` suppressions from _.editorconfig_ files, project files, and `#pragma warning` blocks.
