> This diagnostic is retired. `ContainerResource.ShellExecution` is now a stable API, so it no longer reports `ASPIRECONTAINERSHELLEXECUTION001`.

The `ShellExecution` property on `ContainerResource` controls whether custom arguments are wrapped for shell execution. You no longer need to suppress this diagnostic. You can remove any existing `NoWarn`, `.editorconfig`, or `#pragma warning disable` suppressions for it.

## Behavior

```csharp title="AppHost.cs"
var builder = DistributedApplication.CreateBuilder(args);

var container = builder.AddContainer("hello", "alpine")
    .WithEntrypoint("/bin/sh")
    .WithArgs("echo", "'hello world'");

container.Resource.ShellExecution = true;
```

- `null` (the default) and `false` pass arguments individually.
- `true` passes `-c` followed by the space-joined arguments, without quoting or escaping.

`ShellExecution` doesn't choose a shell. The configured entrypoint, or the image's default entrypoint, must support `-c`. This is a local-orchestration setting, not a deployment-publishing contract.
