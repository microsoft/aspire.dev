## 🆙 Upgrade to Aspire 17.0

<span id="upgrade-to-aspire-17"></span>
<br />

:::caution
Review the [Breaking changes](#breaking-changes) before upgrading.
:::

For general purpose upgrade guidance, see [Upgrade Aspire](/whats-new/upgrade-aspire/).

Once Aspire 17.0 is available on the stable channel, use the [`aspire update` command](/reference/cli/commands/aspire-update/):

<Steps>

1. Update the Aspire CLI itself:

   ```bash title="Aspire CLI — Update the CLI"
   aspire update --self
   ```

1. Update your projects from the repository root:

   ```bash title="Aspire CLI — Update all Aspire packages"
   aspire update
   ```

</Steps>

<LearnMore>
  For more details on installing the Aspire CLI, see [Install the
  CLI](/get-started/install-cli/).
</LearnMore>

## 🐳 Default container image updates

<span id="dashboard-image-update"></span>

Generated Docker Compose and Kubernetes deployments now reference the published Aspire `17.0` dashboard image instead of the `13.6` image used by earlier 17.0 preview builds:

```yaml
# Before
image: "mcr.microsoft.com/aspire/nightly/dashboard:13.6"
```

```yaml
# After
image: "mcr.microsoft.com/aspire/nightly/dashboard:17.0"
```

Without an explicit override, publishers resolve the dashboard tag from the Aspire product version, so this applies automatically when you publish with Aspire 17.0. This doesn't change the dashboard image repository or switch generated deployments to the `latest` tag.

## ⚠️ Breaking changes

<span id="breaking-changes"></span>

| Change                                                                                              | Migration                                                                                              |
| --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `ResourceUrlAnnotation.DisplayOrder` changed from a field to a property                             | Rebuild assemblies that use the field.                                                                 |
| Legacy `Aspire.RabbitMQ.Client.v6` and `Aspire.MongoDB.Driver.v2` packages removed                  | Switch to `Aspire.RabbitMQ.Client` and `Aspire.MongoDB.Driver`, and migrate to the 7.x and 3.x client libraries. |
| Azure Cosmos DB `configureClientOptions` now receives `IServiceProvider`                            | Add the service-provider parameter to callbacks and rebuild binaries that call these methods.          |
| Docker Swarm `UpdateConfig.MaxFailureRatio` changed from `string?` to `double?`                    | Assign a number such as `0.3` instead of a string such as `"0.3"`.                                     |

### `ResourceUrlAnnotation.DisplayOrder` is now a property

`DisplayOrder` changed from an obsolete public field to a read/write property. Its behavior is unchanged: higher values display higher in the dashboard URL list.

Rebuild assemblies that access the field. Typical C# reads and assignments need no changes.

For details, see [microsoft/aspire#20637](https://github.com/microsoft/aspire/pull/20637).

### Legacy RabbitMQ and MongoDB client packages removed

Starting in Aspire 17.0, new releases no longer include `Aspire.RabbitMQ.Client.v6` or `Aspire.MongoDB.Driver.v2`. Previously published versions of these packages remain available on NuGet.

If your app references either legacy package, replace it with the corresponding current integration:

| Removed package             | Replacement package      | Client library version |
| --------------------------- | ------------------------ | ---------------------- |
| `Aspire.RabbitMQ.Client.v6` | `Aspire.RabbitMQ.Client` | `RabbitMQ.Client` 7.x  |
| `Aspire.MongoDB.Driver.v2`  | `Aspire.MongoDB.Driver`  | `MongoDB.Driver` 3.x   |

Update any direct client-library package references and migrate code that uses the older driver APIs. Follow the [RabbitMQ .NET Client 7.x migration guide](https://github.com/rabbitmq/rabbitmq-dotnet-client/blob/main/v7-MIGRATION.md) and the [MongoDB .NET/C# Driver 3.0 upgrade guide](https://www.mongodb.com/docs/drivers/csharp/v3.0/upgrade/v3/).

The service registration calls, `AddRabbitMQClient` and `AddMongoDBClient`, remain the same. This removal doesn't change the behavior of the current `Aspire.RabbitMQ.Client` and `Aspire.MongoDB.Driver` packages or the AppHost hosting integrations.

<LearnMore>
  See [Connect to RabbitMQ](/integrations/messaging/rabbitmq/rabbitmq-connect/)
  and [Connect to MongoDB](/integrations/databases/mongodb/mongodb-connect/) for
  current client setup guidance. For the removal details, see
  [microsoft/aspire#20608](https://github.com/microsoft/aspire/pull/20608).
</LearnMore>
### Azure Cosmos DB client options callback receives a service provider

The `configureClientOptions` parameter on the Azure Cosmos DB client integration now has the type `Action<IServiceProvider, CosmosClientOptions>` instead of `Action<CosmosClientOptions>`. This change applies to the client, container, and database registration methods, including their keyed variants.

Add an `IServiceProvider` parameter to each callback. You can use it to resolve services while configuring the client:

```csharp title="Program.cs"
builder.AddAzureCosmosClient(
    "cosmosdb",
    configureClientOptions: static (services, options) =>
    {
        options.ApplicationName = "myapp";
    });
```

The callback runs when the `CosmosClient` is first resolved from dependency injection, not during service registration. An exception in the callback therefore occurs when the client is resolved. Rebuild applications compiled against an earlier version: calls to these methods from older binaries throw `MissingMethodException`, even when they don't pass a callback.

For details, see [microsoft/aspire#19349](https://github.com/microsoft/aspire/pull/19349).

### Docker Swarm `MaxFailureRatio` now requires a number

The `MaxFailureRatio` property on Docker Swarm `UpdateConfig` changed from `string?` to `double?`. Docker Compose requires this value to be a number, so Aspire 17.0 publishes it without quotes.

Change string assignments to numeric assignments:

```diff title="UpdateConfig.cs"
- MaxFailureRatio = "0.3"
+ MaxFailureRatio = 0.3
```

For details, see [microsoft/aspire#21512](https://github.com/microsoft/aspire/pull/21512).
