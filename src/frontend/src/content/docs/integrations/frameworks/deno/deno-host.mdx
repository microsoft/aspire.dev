This reference covers the Deno AppHost API in the [`Aspire.Hosting.JavaScript`](/integrations/frameworks/javascript/) package. For an introduction, see [Get started with the Deno integration](/integrations/frameworks/deno/deno-get-started/).

<Aside type="caution">
  The Deno APIs are experimental and report the `ASPIREDENO001` diagnostic. In C#, suppress it with `#pragma warning disable ASPIREDENO001` or the `NoWarn` MSBuild property.
</Aside>

## Installation

Install the hosting package in your AppHost:

<InstallPackage packageName="Aspire.Hosting.JavaScript" />

Deno must be available on `PATH` when Aspire runs the resource locally.

## Add a Deno app

<ApiReference name="Aspire.Hosting.JavaScriptHostingExtensions.AddDenoApp" /> adds a <ApiReference name="Aspire.Hosting.JavaScript.DenoAppResource" /> that runs a script from an app directory. In run mode, Aspire executes `deno run -A <script>`.

<Tabs syncKey='aspire-lang'>
<TabItem id='csharp' label='C#'>

```csharp title="AppHost.cs"
using Aspire.Hosting.JavaScript;

var builder = DistributedApplication.CreateBuilder(args);

#pragma warning disable ASPIREDENO001
var api = builder.AddDenoApp("deno-api", "../deno-api", "main.ts");
#pragma warning restore ASPIREDENO001

builder.Build().Run();
```

</TabItem>
<TabItem id='typescript' label='TypeScript'>

```typescript title="apphost.mts"
import { createBuilder } from './.aspire/modules/aspire.mjs';

const builder = await createBuilder();

const api = await builder.addDenoApp('deno-api', '../deno-api', 'main.ts');

await builder.build().run();
```

</TabItem>
</Tabs>

`name` identifies the dashboard resource. `appDirectory` is resolved from the AppHost directory and becomes the working directory. `scriptPath` is the entrypoint, relative to the app directory.

Deno's built-in OpenTelemetry support is enabled through the `OTEL_DENO` environment variable, so traces, metrics, and logs flow to the Aspire dashboard without an application-level SDK.

## Choose how the app runs

By default the resource runs the script. Use these methods to switch modes:

| API | Deno command |
| --- | --- |
| <ApiReference name="Aspire.Hosting.JavaScriptHostingExtensions.WithDenoRun" /> | `deno run <script>` (default) |
| <ApiReference name="Aspire.Hosting.JavaScriptHostingExtensions.WithDenoTask" /> | `deno task <taskName>` |
| <ApiReference name="Aspire.Hosting.JavaScriptHostingExtensions.WithDenoServe" /> | `deno serve <script>` |

<Tabs syncKey='aspire-lang'>
<TabItem id='csharp' label='C#'>

```csharp title="AppHost.cs"
using Aspire.Hosting.JavaScript;

var builder = DistributedApplication.CreateBuilder(args);

#pragma warning disable ASPIREDENO001
var web = builder.AddDenoApp("web", "../web", "main.ts")
    .WithDenoTask("dev");
#pragma warning restore ASPIREDENO001

builder.Build().Run();
```

</TabItem>
<TabItem id='typescript' label='TypeScript'>

```typescript title="apphost.mts"
import { createBuilder } from './.aspire/modules/aspire.mjs';

const builder = await createBuilder();

const web = await builder
  .addDenoApp('web', '../web', 'main.ts')
  .withDenoTask('dev');

await builder.build().run();
```

</TabItem>
</Tabs>

Task mode runs the task defined in the app's `deno.json` or `deno.jsonc`; permissions are defined by the task itself and Aspire doesn't emit permission flags for it. Serve mode adds an `http` endpoint if one doesn't exist, sets `PORT`, and passes `--host` and `--port` to `deno serve`. Use <ApiReference name="Aspire.Hosting.JavaScriptHostingExtensions.WithDenoWatch" /> to add `--watch`, or pass `hmr: true` for `--watch-hmr`.

## Control permissions

In run mode, Aspire passes `-A` (allow all) to Deno unless you configure a granular allow with `WithDenoAllow` (or call `WithDenoAllowAll(false)`). Deny flags alone don't change the default. Generated containers use the more restrictive `--allow-net --allow-env` default. Use the permission methods to grant or deny specific capabilities:

- <ApiReference name="Aspire.Hosting.JavaScriptHostingExtensions.WithDenoAllow" /> emits `--allow-<kind>`, optionally scoped to values.
- <ApiReference name="Aspire.Hosting.JavaScriptHostingExtensions.WithDenoDeny" /> emits `--deny-<kind>`, optionally scoped to values.
- <ApiReference name="Aspire.Hosting.JavaScriptHostingExtensions.WithDenoAllowAll" /> emits `--allow-all`.

The `kind` argument is a <ApiReference name="Aspire.Hosting.JavaScript.DenoPermissionKind" /> value such as `Net`, `Read`, or `Write`.

<Tabs syncKey='aspire-lang'>
<TabItem id='csharp' label='C#'>

```csharp title="AppHost.cs"
using Aspire.Hosting.JavaScript;

var builder = DistributedApplication.CreateBuilder(args);

#pragma warning disable ASPIREDENO001
var api = builder.AddDenoApp("deno-api", "../deno-api", "main.ts")
    .WithDenoAllow(DenoPermissionKind.Net, "api.example.com")
    .WithDenoAllow(DenoPermissionKind.Env)
    .WithDenoDeny(DenoPermissionKind.Write);
#pragma warning restore ASPIREDENO001

builder.Build().Run();
```

</TabItem>
<TabItem id='typescript' label='TypeScript'>

```typescript title="apphost.mts"
import {
  createBuilder,
  DenoPermissionKind,
} from './.aspire/modules/aspire.mjs';

const builder = await createBuilder();

const api = await builder.addDenoApp('deno-api', '../deno-api', 'main.ts');

await api.withDenoAllow(DenoPermissionKind.Net, ['api.example.com']);
await api.withDenoAllow(DenoPermissionKind.Env, []);
await api.withDenoDeny(DenoPermissionKind.Write, []);

await builder.build().run();
```

</TabItem>
</Tabs>

## Configure Deno flags

Dedicated methods cover common Deno flags:

| API | Effect |
| --- | --- |
| <ApiReference name="Aspire.Hosting.JavaScriptHostingExtensions.WithDenoConfig" /> | `--config <file>` |
| <ApiReference name="Aspire.Hosting.JavaScriptHostingExtensions.WithDenoImportMap" /> | `--import-map <file>` |
| <ApiReference name="Aspire.Hosting.JavaScriptHostingExtensions.WithDenoLock" /> | `--lock <file>` |
| <ApiReference name="Aspire.Hosting.JavaScriptHostingExtensions.WithDenoNoLock" /> | `--no-lock` |
| <ApiReference name="Aspire.Hosting.JavaScriptHostingExtensions.WithDenoNodeModulesDir" /> | `--node-modules-dir`, optionally with a <ApiReference name="Aspire.Hosting.JavaScript.DenoNodeModulesDirMode" /> |
| <ApiReference name="Aspire.Hosting.JavaScriptHostingExtensions.WithDenoUnstable" /> | `--unstable-<feature>` flags |
| <ApiReference name="Aspire.Hosting.JavaScriptHostingExtensions.WithDenoInspect" /> | `--inspect`, `--inspect-brk`, or `--inspect-wait`, optionally at a `host:port` |

For any other flag, use <ApiReference name="Aspire.Hosting.JavaScriptHostingExtensions.WithDenoRuntimeArgs" /> to add arguments before the entrypoint, and <ApiReference name="Aspire.Hosting.JavaScriptHostingExtensions.WithDenoScriptArgs" /> to pass arguments to the script after the entrypoint.

<Tabs syncKey='aspire-lang'>
<TabItem id='csharp' label='C#'>

```csharp title="AppHost.cs"
using Aspire.Hosting.JavaScript;

var builder = DistributedApplication.CreateBuilder(args);

#pragma warning disable ASPIREDENO001
var api = builder.AddDenoApp("deno-api", "../deno-api", "main.ts")
    .WithDenoConfig("deno.json")
    .WithDenoUnstable("kv")
    .WithDenoRuntimeArgs("--quiet")
    .WithDenoScriptArgs("--verbose");
#pragma warning restore ASPIREDENO001

builder.Build().Run();
```

</TabItem>
<TabItem id='typescript' label='TypeScript'>

```typescript title="apphost.mts"
import { createBuilder } from './.aspire/modules/aspire.mjs';

const builder = await createBuilder();

const api = await builder.addDenoApp('deno-api', '../deno-api', 'main.ts');

await api.withDenoConfig('deno.json');
await api.withDenoUnstable(['kv']);
await api.withDenoRuntimeArgs(['--quiet']);
await api.withDenoScriptArgs(['--verbose']);

await builder.build().run();
```

</TabItem>
</Tabs>

## Install Deno packages before startup

<ApiReference name="Aspire.Hosting.JavaScriptHostingExtensions.WithDeno" /> configures a JavaScript resource to use Deno as its package manager. `AddDenoApp` calls it automatically when the app directory contains a `package.json`, `deno.json`, or `deno.jsonc` file. Unlike npm, Deno doesn't need a separate install step: `deno run` fetches and caches dependencies on first use. Pass `install: true` to create an installer resource that runs `deno install` before the app starts, and `installArgs` to customize that command.

<Tabs syncKey='aspire-lang'>
<TabItem id='csharp' label='C#'>

```csharp title="AppHost.cs"
using Aspire.Hosting.JavaScript;

var builder = DistributedApplication.CreateBuilder(args);

#pragma warning disable ASPIREDENO001
var api = builder.AddDenoApp("deno-api", "../deno-api", "main.ts")
    .WithDeno(install: true);
#pragma warning restore ASPIREDENO001

builder.Build().Run();
```

</TabItem>
<TabItem id='typescript' label='TypeScript'>

```typescript title="apphost.mts"
import { createBuilder } from './.aspire/modules/aspire.mjs';

const builder = await createBuilder();

const api = await builder.addDenoApp('deno-api', '../deno-api', 'main.ts');

await api.withDeno(true);

await builder.build().run();
```

</TabItem>
</Tabs>

## Configure endpoints, environment, and health checks

<ApiReference name="Aspire.Hosting.JavaScript.DenoAppResource" /> supports endpoints, environment variables, references, and service discovery. Use the standard AppHost APIs to expose a port and define a health probe:

<Tabs syncKey='aspire-lang'>
<TabItem id='csharp' label='C#'>

```csharp title="AppHost.cs"
using Aspire.Hosting.JavaScript;

var builder = DistributedApplication.CreateBuilder(args);

#pragma warning disable ASPIREDENO001
var api = builder.AddDenoApp("deno-api", "../deno-api", "main.ts")
    .WithHttpEndpoint(port: 8000, env: "PORT")
    .WithEnvironment("LOG_LEVEL", "debug")
    .WithHttpHealthCheck("/health");
#pragma warning restore ASPIREDENO001

builder.Build().Run();
```

</TabItem>
<TabItem id='typescript' label='TypeScript'>

```typescript title="apphost.mts"
import { createBuilder } from './.aspire/modules/aspire.mjs';

const builder = await createBuilder();

const api = await builder
  .addDenoApp('deno-api', '../deno-api', 'main.ts')
  .withHttpEndpoint({ port: 8000, env: 'PORT' })
  .withEnvironment('LOG_LEVEL', 'debug')
  .withHttpHealthCheck({ path: '/health' });

await builder.build().run();
```

</TabItem>
</Tabs>

The application must read the `PORT` variable and listen on that port. It also needs the Deno permissions to read its environment and serve network traffic. <ApiReference name="Aspire.Hosting.ResourceBuilderExtensions.WithHttpHealthCheck" /> makes Aspire poll the specified HTTP path. Other resources can use <ApiReference name="Aspire.Hosting.ResourceBuilderExtensions.WithReference" /> to discover a Deno app.

## Publishing behavior

When you publish, Aspire generates a Dockerfile for the Deno app. `WithDeno` configures the `denoland/deno` build image when no image is specified, so Deno is available during the container build. The generated container runs with the restrictive `--allow-net --allow-env` permissions; use the permission methods or a custom Dockerfile if the app needs more. The `manual` node modules mode isn't supported by the generated Dockerfile, so use `auto` or provide your own Dockerfile.
