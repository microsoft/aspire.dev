[Azure API Management](https://learn.microsoft.com/azure/api-management/) (APIM) is a managed gateway for publishing, securing, and observing APIs. The Aspire Azure API Management hosting integration models an APIM service and its child resources, such as APIs, backends, policies, and products, without hand-authored Bicep.

<Aside type="caution">
`Aspire.Hosting.Azure.ApiManagement` is a prerelease package. Its APIs might change in future releases.
</Aside>

APIM is a deploy-only parent resource. It's omitted during `aspire run`, while `aspire deploy` provisions the service and the children declared beneath it. You don't need an execution-mode guard in your AppHost.

## Hosting integration

To access the APIs, add the [📦 Aspire.Hosting.Azure.ApiManagement](https://www.nuget.org/packages/Aspire.Hosting.Azure.ApiManagement) NuGet package to your AppHost project.

<InstallPackage packageName="Aspire.Hosting.Azure.ApiManagement" />

The integration models the service as `AzureApiManagementResource`, with child resources including `AzureApiManagementApiResource`, `AzureApiManagementOperationResource`, `AzureApiManagementBackendResource`, `AzureApiManagementBackendPoolResource`, `AzureApiManagementPolicyFragmentResource`, `AzureApiManagementProductResource`, and `AzureApiManagementNamedValueResource`.

### Add an API Management service and route to a workload

Call `AddAzureApiManagement` to add the service, then call `AddApi` with a compute resource to expose it through the gateway:

```csharp title="AppHost.cs"
var builder = DistributedApplication.CreateBuilder(args);

var catalog = builder.AddProject<Projects.Catalog>("catalog")
    .WithExternalHttpEndpoints();

var apim = builder.AddAzureApiManagement("apim", new()
{
    PublisherEmail = "api-owners@example.com",
    PublisherName = "Contoso APIs",
});

apim.AddApi(
    "catalog-api",
    catalog,
    path: "catalog",
    subscriptionRequired: false);

// After adding all resources, run the app...
builder.Build().Run();
```

The compute-targeted `AddApi` overload creates an API, a reusable APIM backend, and root and catch-all operations for each supported HTTP method. These operations forward requests for the API path and its descendants to the workload's deployed endpoint. APIs require an APIM subscription key by default.

<Aside type="note">
When you publish or deploy, the compute resource you pass to `AddApi` must have an Azure compute environment, because APIM routes to the workload's deployed endpoint. For example, add an environment with `AddAzureContainerAppEnvironment` and assign it with `WithComputeEnvironment`, as shown in [Import OpenAPI definitions](#import-openapi-definitions). If the resource has no compute environment, `aspire publish` and `aspire deploy` fail. `aspire run` isn't affected, because APIM is omitted in run mode.
</Aside>

Supported service SKUs are Consumption, Developer, Basic, Basic v2, Standard, Standard v2, Premium, and Premium v2. The integration validates SKU and capacity combinations.

### Import OpenAPI definitions

Import operations from a deployed workload's OpenAPI endpoint:

```csharp title="AppHost.cs"
var environment = builder.AddAzureContainerAppEnvironment("env");

catalog.WithComputeEnvironment(environment)
    .WithExternalHttpEndpoints();

apim.AddApi("catalog-api", catalog, "catalog", subscriptionRequired: false)
    .WithOpenApiEndpoint("/openapi/v1.json");
```

APIM imports operations, parameters, schemas, and descriptions after the workload is deployed. The document endpoint must be reachable by the APIM control plane. For private workloads, use a JSON or YAML file available at publish time instead:

```csharp title="AppHost.cs"
apim.AddApi("catalog-api", catalog, "catalog")
    .WithOpenApiDocument("../Catalog/openapi.json");
```

### Backends and backend pools

Add generic HTTP or SOAP backends with `AddBackend`, or specialized backends for Azure OpenAI, Foundry, and Blob Storage. Specialized backends configure managed identity authentication and required role assignments. Azure OpenAI and Foundry backends also configure HTTP 429 circuit breakers. Group backends into weighted, priority-based pools:

```csharp title="AppHost.cs"
var primary = apim.AddFoundryBackend("primary", primaryDeployment);
var secondary = apim.AddFoundryBackend("secondary", secondaryDeployment);

var pool = apim.AddBackendPool("openai-pool")
    .WithBackend(primary, priority: 1, weight: 3)
    .WithBackend(secondary, priority: 1, weight: 1);

apim.AddOpenAIApi(
        "openai-api",
        path: "openai",
        subscriptionRequired: false)
    .WithBackend(pool);
```

Members at the same priority receive weighted traffic. Lower priority numbers are preferred, and the next priority is used when every backend in the preferred group has an open circuit.

### Policies, products, and more

You can also declare:

- Service-, API-, and operation-level policies, composable inbound statements, and reusable policy fragments.
- Products, API associations, subscriptions, approval settings, and subscription limits.
- Named values that are literals, secret parameters, or Key Vault-backed.
- Service-wide and per-API Application Insights diagnostics.
- Key Vault-backed custom domains and certificates.

<Aside type="caution">
Policies accept arbitrary APIM policy XML, and the service can expose public ingress. TLS certificate-chain and hostname validation are enabled by default. Creating role assignments requires `Microsoft.Authorization/roleAssignments/write` on each target scope.
</Aside>

### Use an existing API Management service

Call `PublishAsExisting` to adopt an existing service. Aspire treats the service as read-only while managing the child resources declared in your AppHost. Set `Sku` explicitly to the existing service's actual pricing tier, even when it's Developer. Aspire uses this value to validate SKU-dependent child resources and throws at publish time if it's omitted:

```csharp title="AppHost.cs"
var apim = builder.AddAzureApiManagement("apim", new()
{
    PublisherEmail = "api-owners@example.com",
    PublisherName = "Contoso APIs",
    Sku = AzureApiManagementSku.Premium,
}).PublishAsExisting(
    "shared-apim",
    resourceGroup: "shared-infrastructure");

var backend = apim.AddBackend(
    "catalog-backend",
    ReferenceExpression.Create($"https://catalog.example.com"));

apim.AddApi("catalog-api", "catalog")
    .WithBackend(backend);
```

Service-level networking, identities, and custom domains can't be changed through adoption.

APIM uses a user-assigned managed identity for backend authentication and Key Vault access. Aspire creates and attaches one for new services, but it doesn't attach identities to existing services. If an existing service uses managed-identity backends or Key Vault-backed named values, supply an identity that's already attached to the service:

```csharp title="AppHost.cs"
var identity = builder.AddAzureUserAssignedIdentity("existing-apim-identity")
    .PublishAsExisting(
        "shared-apim-identity",
        resourceGroup: "shared-infrastructure");

apim.WithAzureUserAssignedIdentity(identity);
```

Diagnostics can't be configured when an existing APIM service is adopted from another resource group or subscription. Aspire-created role assignments deploy at the target resource's scope and can target resources in other resource groups.

### Networking

- Developer and Premium support classic external or internal VNet injection.
- Standard v2 and Premium v2 support outbound VNet integration through a dedicated `/27` or larger subnet.
- Premium v2 supports inbound and outbound VNet injection through a dedicated subnet.
- APIM with classic external VNet injection (Developer or Premium) can publicly front an internal Container Apps environment in a separate subnet of the same virtual network. Configure the environment with `WithDelegatedSubnet` and then `WithInternalLoadBalancer(vnet)`, which provisions a private DNS zone and wildcard record for the environment's default domain. Container Apps Express environments don't support an internal load balancer.
- Inbound private endpoints create the `privatelink.azure-api.net` DNS resources for new or existing services.

Private endpoints can't be combined with classic VNet injection or Premium v2 injection. Consumption and Basic v2 don't support private endpoints. Internal classic and Premium v2 injection require customer-managed DNS for APIM's private VIP.

<Aside type="note">
Adding a private endpoint doesn't make APIM private-only. To restrict gateway access, [disable public network access](https://learn.microsoft.com/azure/api-management/private-endpoint#optionally-disable-public-network-access) separately after the private endpoint is configured and approved.
</Aside>

### Current limitations

The integration doesn't yet model automatic public-access disabling, backend client certificates and credential collections, consumer-safe subscription-key references, multi-region, zone, or autoscale configuration, or API versions and revisions.
