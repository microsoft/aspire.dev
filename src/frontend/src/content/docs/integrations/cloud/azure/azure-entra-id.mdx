This article describes the federated managed identity credential APIs of the `Aspire.Hosting.Azure.EntraId` hosting integration. A federated credential lets a deployed workload authenticate as an Entra ID app registration with no client secret or certificate.

## Federated identity credential with managed identity

For deployed applications, use a federated managed identity credential so that no secret is stored. Aspire creates the registration, and the registration trusts the managed identity of each workload that references it:

```csharp title="C# — AppHost.cs"
var entraWeb = builder.AddEntraIdApplication("entra-web")
                      .PublishWithFederatedManagedIdentityCredential();

builder.AddProject<Projects.Web>("web")
       .WithReference(entraWeb);
```

Referencing the registration makes the workload need a user-assigned managed identity when published, the same way referencing an Azure resource does. The workload uses the identity it already has (for example from `WithAzureUserAssignedIdentity`), or the Azure environment creates one.

The generated Bicep adds a `Microsoft.Graph/applications/federatedIdentityCredentials` resource with:

- **Issuer**: the tenant's v2.0 endpoint.
- **Subject**: the identity's **object (principal) ID**.
- **Audience**: the token-exchange audience of the application's cloud. Azure public, US Government, and China are supported; other clouds fail with an error.

The workload receives the identity's **client ID** as `ManagedIdentityClientId`. Deployment order is identity, then registration, then workload.

### Trust specific workloads or identities

Pass a compute resource or an `AzureUserAssignedIdentityResource` to limit the trust. A compute resource passed this way must also reference the registration, and only it receives the credential:

```csharp title="C# — AppHost.cs"
var entraWeb = builder.AddEntraIdApplication("entra-web");
var web = builder.AddProject<Projects.Web>("web").WithReference(entraWeb);

entraWeb.PublishWithFederatedManagedIdentityCredential(web);
```

```csharp title="C# — AppHost.cs"
var identity = builder.AddAzureUserAssignedIdentity("web-identity");
var entraWeb = builder.AddEntraIdApplication("entra-web")
                      .PublishWithFederatedManagedIdentityCredential(identity);

builder.AddProject<Projects.Web>("web")
       .WithAzureUserAssignedIdentity(identity)
       .WithReference(entraWeb);
```

A validation step runs after the `azure-prepare-resources` step and fails, naming the resource, when a trusted compute resource has no managed identity.

<Aside type="note">
The federated credential only changes how the app authenticates as itself. Interactive user sign-in still needs a redirect URI registered on the app registration, for example with `WithRedirectUris(web.GetEndpoint("https"), "/signin-oidc")`.
</Aside>

Managed identities exist only in Azure, so `PublishWithFederatedManagedIdentityCredential` isn't used when running locally. Add another credential, such as a client secret, for local development.

### Existing registrations

Aspire never modifies an existing registration, so `PublishWithFederatedManagedIdentityCredential` throws for `AddExistingEntraApplication`. Create the trust yourself, then use `WithFederatedManagedIdentityCredential` (previously `WithFicMsi`) with the managed identity's client ID. It only configures the app, and applies when running locally as well as when publishing:

```csharp title="C# — AppHost.cs"
var entraWeb = builder.AddExistingEntraApplication("entra-web", tenantId: tenantId, clientId: webClientId)
                      .WithFederatedManagedIdentityCredential("00001111-aaaa-2222-bbbb-3333cccc4444");
```

Add a federated credential to the registration with the tenant's v2.0 issuer (`https://login.microsoftonline.com/<tenant-id>/v2.0` in the Azure public cloud), the identity's principal (object) ID as the subject, and `api://AzureADTokenExchange` as the audience. Pass the identity's **client ID**, not its principal ID. For details, see [Configure an application to trust a managed identity](https://learn.microsoft.com/entra/workload-id/workload-identity-federation-config-app-trust-managed-identity).

## Require a managed identity on a compute resource

`ManagedIdentityRequiredAnnotation` is an experimental API (`ASPIREAZURE003`). When added to a compute resource, Aspire gives it a managed identity even when it has no role assignments. Referencing an Entra ID application adds this annotation automatically.
