Aspire provides several AI hosting and client integrations that enable you to work with different AI services and platforms. This article is a compatibility reference showing which client integrations work with which hosting integrations, along with the recommended pairings and AppHost API examples.

## Compatibility matrix

The following table shows the compatibility between Aspire AI hosting and client integrations:

| **Hosting Integration** | **Aspire.OpenAI** | **Aspire.Azure.AI.Extensions.OpenAI** | **Aspire.Azure.AI.Projects** |
|--|--|--|--|
| `Aspire.Hosting.Foundry` | ⚠️ Partial — Foundry Local only (preferred) | ✅ Yes — deployments and projects (preferred) | ⚠️ Partial — projects only |
| `Aspire.Hosting.Azure.CognitiveServices` | ❌ No | ✅ Yes (preferred) | ❌ No |
| `Aspire.Hosting.OpenAI` | ✅ Yes (preferred) | ⚠️ Partial — `AddOpenAIClientFromConfiguration` only | ❌ No |

<Aside type="note" title="Legend">

- ✅ **Yes**: The client integration is compatible with the hosting integration.
- ⚠️ **Partial**: The client integration has limited model, API, or hosting-mode support.
- ❌ **No**: The client integration does not support the hosting environment.
- **(preferred)**: The recommended client integration for this hosting integration.

</Aside>

:::note[Upgrading to Aspire 17?]
`Aspire.Azure.AI.OpenAI` and `Aspire.Azure.AI.Inference` are discontinued. See [Migrate from Aspire.Azure.AI.Inference or Aspire.Azure.AI.OpenAI](/integrations/cloud/azure/azure-ai-foundry/azure-ai-foundry-connect/#migrate-from-aspireazureaiinference-or-aspireazureaiopenai).
:::

## Recommended pairings

In general, use an Aspire client integration when one supports the resource and its authentication method. Use **Aspire.OpenAI** for OpenAI-compatible resources that provide an API key, including Foundry Local. For Azure OpenAI and cloud-provisioned Microsoft Foundry resources, which authenticate with Microsoft Entra ID, use **Aspire.Azure.AI.Extensions.OpenAI**.

### Microsoft Foundry

For Foundry Local resources, use the **Aspire.OpenAI** client integration. It provides dependency injection and telemetry for the OpenAI-compatible endpoint and the API key that Foundry Local exposes. For cloud-provisioned Microsoft Foundry resources, use **Aspire.Azure.AI.Extensions.OpenAI**: `AddAzureOpenAIClient` for model deployments, or `AddAzureProjectOpenAIClient` for Foundry projects. Use **Aspire.Azure.AI.Projects** (`AddAzureAIProjectClient`) for project and agent-management operations.

For more information, see [Microsoft Foundry integration](/integrations/cloud/azure/azure-ai-foundry/azure-ai-foundry-get-started/).

#### Hosting integration

The [Aspire.Hosting.Foundry](https://www.nuget.org/packages/Aspire.Hosting.Foundry) package provides the hosting integration. In your app host project:

builder.AddDotnetProject("exampleproject", "../ExampleProject/ExampleProject.csproj")
    .WithReference(chat);

#### Client integration

For Foundry Local, the [Aspire.OpenAI](https://www.nuget.org/packages/Aspire.OpenAI) package provides the recommended client integration. For its configuration sample, see [Connect with Aspire.OpenAI](/integrations/cloud/azure/azure-ai-foundry/azure-ai-foundry-connect/#connect-with-aspireopenai-foundry-local). For cloud-provisioned Foundry resources, the [Aspire.Azure.AI.Extensions.OpenAI](https://www.nuget.org/packages/Aspire.Azure.AI.Extensions.OpenAI) package provides the client integration:

```csharp title="Program.cs"
builder.AddAzureOpenAIClient("chat").AddChatClient();
```

For Foundry projects and the [Aspire.Azure.AI.Projects](https://www.nuget.org/packages/Aspire.Azure.AI.Projects) package, see [Connect to a Foundry project](/integrations/cloud/azure/azure-ai-foundry/azure-ai-foundry-connect/#connect-to-a-foundry-project).

## Connection string formats

Understanding how hosting and client integrations communicate through connection strings can help you troubleshoot connectivity issues and understand the underlying mechanics.

Each hosting integration generates connection strings in different formats that are consumed by the client integrations.

### Hosting integration connection strings

#### Aspire.Hosting.Foundry

**Azure:**

```
Endpoint={Endpoint};EndpointAIInference={EndpointAIInference}models
```

**Foundry Local:**

```
Endpoint={EmulatorServiceUri};Key={ApiKey}
```

**Deployment:**

```
{Parent};Deployment={DeploymentName}
```

#### Aspire.Hosting.Azure.CognitiveServices

**Deployment:**

```
{ConnectionString};Deployment={DeploymentName}
```

#### Aspire.Hosting.OpenAI

```
Endpoint={Endpoint};Key={Key};Model={Model}
```

### Client integration connection string requirements

#### Aspire.OpenAI

Expects connection strings in the format:

```
Endpoint={Endpoint};Key={Key};Deployment={Deployment};Model={Model}
```

Uses either `Deployment` or `Model` (in that order). `Deployment` is set by `Aspire.Hosting.Azure.CognitiveServices` while `Model` is set by `Aspire.Hosting.OpenAI`.

#### Aspire.Azure.AI.Extensions.OpenAI

`AddAzureOpenAIClient` expects an HTTPS Azure OpenAI or Foundry account endpoint:

```
Endpoint={Endpoint};Key={Key};Deployment={Deployment}
```

`Key` is optional; without it, the client uses Microsoft Entra ID. A bare endpoint URI is also accepted. Chat and embedding helpers use either `Deployment` or `Model`, but not both.

`AddAzureProjectOpenAIClient` expects a Foundry project endpoint and rejects `Key`:

```
Endpoint=https://{account}.services.ai.azure.com/api/projects/{project}
```

`AddOpenAIClientFromConfiguration` selects an Azure account, Foundry project, or OpenAI-compatible registration from the endpoint. Endpoints on Azure hosts are treated as Azure; use `IsAzure=true` or `IsAzure=false` to override detection.

#### Aspire.Azure.AI.Projects

Expects a Foundry project endpoint, either as a bare URI or in the format:

```
Endpoint=https://{account}.services.ai.azure.com/api/projects/{project}
```

`Key` isn't supported; the client uses Microsoft Entra ID.
