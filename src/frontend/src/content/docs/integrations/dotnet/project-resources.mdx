This page is a reference for AppHosts that still use the legacy `ProjectResource` model through `AddProject`, `AddCSharpApp`, or TypeScript `addProject`.

:::caution[These APIs are obsolete]
Starting in Aspire 17, `AddProject` and `AddCSharpApp` are obsolete. For new resources, use `AddDotnetProject` from the [.NET / C# integration](/integrations/frameworks/dotnet/dotnet-host/). To move an existing AppHost, see [Migrate to the new DotnetProjectResource](/integrations/dotnet/migrate-dotnet-project-resource/).
:::

## Add a legacy project resource

<Tabs syncKey="aspire-lang">
<TabItem id="csharp" label="C#">

A C# AppHost references the target project with a `ProjectReference` marked as an Aspire project resource:

```xml title="AppHost.csproj"
<ItemGroup>
  <ProjectReference Include="..\ApiService\ApiService.csproj"
                    IsAspireProjectResource="true"
                    ReferenceOutputAssembly="false" />
</ItemGroup>
```

When the AppHost builds, Aspire generates a metadata type in the `Projects` namespace for each marked reference. <ApiReference name="Aspire.Hosting.ProjectResourceBuilderExtensions.AddProject" /> uses that type to locate the project:

```csharp title="AppHost.cs"
var builder = DistributedApplication.CreateBuilder(args);

var api = builder.AddProject<Projects.ApiService>("api");

builder.Build().Run();
```

<ApiReference name="Aspire.Hosting.ProjectResourceBuilderExtensions.AddCSharpApp" /> takes a path to a project, directory, or file-based `.cs` app instead and doesn't need a `ProjectReference`:

```csharp title="AppHost.cs"
var worker = builder.AddCSharpApp("worker", "../Worker/Worker.csproj");
```

</TabItem>
<TabItem id="typescript" label="TypeScript">

A TypeScript AppHost passes the path to the `.csproj` file:

```typescript title="apphost.mts"
import { createBuilder } from './.aspire/modules/aspire.mjs';

const builder = await createBuilder();

const api = await builder.addProject("api", "../ApiService/ApiService.csproj");

await builder.build().run();
```

</TabItem>
</Tabs>

Legacy project resources support the same resource APIs as other Aspire resources, such as `WithReference`, `WaitFor`, endpoints, and environment variables. For guidance that applies to all .NET project resources, see:

- [Launch profiles](/integrations/dotnet/launch-profiles/) for profile selection and endpoints from _launchSettings.json_ and Kestrel configuration.
- [Inner-loop networking](/fundamentals/networking-overview/) for ports, proxies, and replicas.
- [Set up .NET / C# apps in the AppHost](/integrations/frameworks/dotnet/dotnet-host/) for endpoint filtering, coordinated builds, and publishing.

## Select a launch profile

Legacy APIs take the launch profile as a method argument rather than an options object:

<Tabs syncKey="aspire-lang">
<TabItem id="csharp" label="C#">

```csharp title="AppHost.cs"
builder.AddProject<Projects.InventoryService>("inventoryservice", launchProfileName: "https");

// Run without a launch profile
builder.AddProject<Projects.Worker>("worker", launchProfileName: null);

// Use Kestrel endpoints instead of launch profile endpoints
builder.AddProject<Projects.Catalog>("catalog", configure: static project =>
{
    project.ExcludeLaunchProfile = true;
    project.ExcludeKestrelEndpoints = false;
});
```

</TabItem>
<TabItem id="typescript" label="TypeScript">

```typescript title="apphost.mts"
await builder.addProject("inventoryservice", "../InventoryService/InventoryService.csproj", {
    launchProfileOrOptions: "https",
});
```

</TabItem>
</Tabs>

`AddDotnetProject` exposes the same choices through `launchProfileName`, `excludeLaunchProfile`, and `excludeKestrelEndpoints` options. See [Configure options](/integrations/frameworks/dotnet/dotnet-host/#configure-options).

## Customize generated project types

To rename a generated `Projects.*` type, for example when two projects have the same name, set `AspireProjectMetadataTypeName` on the `ProjectReference`. `AddDotnetProject` takes a path, so it doesn't use generated types or this metadata.

<LearnMore>
  For the full set of `ProjectReference` metadata, see [Generated project metadata](/get-started/aspire-sdk/#generated-project-metadata).
</LearnMore>
