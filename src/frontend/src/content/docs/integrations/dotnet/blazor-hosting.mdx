This article is the reference for the Aspire Blazor hosting integration. It lists the AppHost APIs — with examples for both `AppHost.cs` and `apphost.mts` — that you use to model Blazor WebAssembly projects and a Blazor Gateway in your [`AppHost`](/get-started/app-host/) project.

If you're new to this integration, start with [Get started with Blazor hosting](/integrations/dotnet/blazor-get-started/). For how apps connect through the gateway and service discovery properties, see [Connect Blazor apps and APIs](../blazor-connect/).

## Installation

To start building an Aspire app that uses Blazor hosting, install the [📦 Aspire.Hosting.Blazor](https://www.nuget.org/packages/Aspire.Hosting.Blazor) NuGet package:

<Tabs syncKey='aspire-lang'>
<TabItem id='csharp' label='C#'>

```bash title="Terminal"
aspire add Aspire.Hosting.Blazor
```

<LearnMore>
  Learn more about [`aspire add`](/reference/cli/commands/aspire-add/) in the
  command reference.
</LearnMore>

Or, choose a manual installation approach:

```csharp title="AppHost.cs"
#:package Aspire.Hosting.Blazor@*
```

```xml title="AppHost.csproj"
<PackageReference Include="Aspire.Hosting.Blazor" Version="*" />
```

</TabItem>
<TabItem id='typescript' label='TypeScript'>

```bash title="Terminal"
aspire add Aspire.Hosting.Blazor
```

<LearnMore>
  Learn more about [`aspire add`](/reference/cli/commands/aspire-add/) in the
  command reference.
</LearnMore>

This updates your `aspire.config.json` with the Blazor hosting package:

```json title="aspire.config.json" ins={3}
{
  "packages": {
    "Aspire.Hosting.Blazor": "%ASPIRE_VERSION%"
  }
}
```

</TabItem>
</Tabs>

## Add a Blazor WebAssembly app

Use <ApiReference name="Aspire.Hosting.BlazorGatewayExtensions.AddBlazorWasmApp" /> to add a Blazor WebAssembly project to the AppHost model. In TypeScript AppHosts, this API is named `addBlazorWasmProject`. Aspire doesn't launch the WebAssembly app as its own process; a [Blazor Gateway](#add-a-blazor-gateway) serves it to the browser.

<Tabs syncKey='aspire-lang'>
<TabItem id='typescript' label='TypeScript'>

```typescript title="apphost.mts" twoslash
import { createBuilder } from './.aspire/modules/aspire.mjs';

const builder = await createBuilder();

const api = await builder.addDotnetProject('api', '../MyApi/MyApi.csproj');

const blazorApp = await builder
  .addBlazorWasmProject('app', '../MyBlazorApp/MyBlazorApp.csproj')
  .withReference(api);

await builder.build().run();
```

</TabItem>
<TabItem id='csharp' label='C#'>

```csharp title="AppHost.cs"
#pragma warning disable ASPIREBLAZOR001

var builder = DistributedApplication.CreateBuilder(args);

var api = builder.AddDotnetProject("api", "../MyApi/MyApi.csproj");

var blazorApp = builder.AddBlazorWasmApp("app", "../MyBlazorApp/MyBlazorApp.csproj")
    .WithReference(api);

builder.Build().Run();
```

</TabItem>
</Tabs>

## Add a Blazor Gateway

Use <ApiReference name="Aspire.Hosting.BlazorGatewayExtensions.AddDotnetProjectBlazorGateway" /> to add the Blazor Gateway resource. The gateway is the browser-facing endpoint for your Blazor app: it serves the WebAssembly client and forwards the client's API and telemetry traffic. Aspire provides the gateway, so you don't need to create a gateway project.

<Tabs syncKey='aspire-lang'>
<TabItem id='typescript' label='TypeScript'>

```typescript title="apphost.mts" twoslash
import { createBuilder } from './.aspire/modules/aspire.mjs';

const builder = await createBuilder();

const gateway = await builder
  .addDotnetProjectBlazorGateway('gateway')
  .withExternalHttpEndpoints();

await builder.build().run();
```

</TabItem>
<TabItem id='csharp' label='C#'>

```csharp title="AppHost.cs"
var builder = DistributedApplication.CreateBuilder(args);

var gateway = builder.AddDotnetProjectBlazorGateway("gateway")
    .WithExternalHttpEndpoints();

builder.Build().Run();
```

</TabItem>
</Tabs>

<ApiReference name="Aspire.Hosting.ResourceBuilderExtensions.WithExternalHttpEndpoints" /> marks the gateway endpoint as externally accessible so browser traffic can reach your app.

:::note[Upgrading to Aspire 17?]
`AddBlazorGateway` creates a gateway based on the legacy `ProjectResource` type. Replace it with `AddDotnetProjectBlazorGateway`; the `WithBlazorClientApp` call stays the same. If you customized the gateway's publishing, review that configuration after you switch. For the broader move off `ProjectResource`, see [Migrate to the new DotnetProjectResource](/integrations/dotnet/migrate-dotnet-project-resource/).
:::

## Associate a client app with the gateway

Use <ApiReference name="Aspire.Hosting.BlazorGatewayExtensions.WithBlazorClientApp" parameterTypes={['Aspire.Hosting.ApplicationModel.IResourceBuilder<Aspire.Hosting.Dotnet.DotnetProjectResource>', 'Aspire.Hosting.ApplicationModel.IResourceBuilder<Aspire.Hosting.BlazorWasmAppResource>', 'string', 'string', 'bool']} /> to bind the WebAssembly app resource to the Blazor Gateway:

<Tabs syncKey='aspire-lang'>
<TabItem id='typescript' label='TypeScript'>

```typescript title="apphost.mts" twoslash
import { createBuilder } from './.aspire/modules/aspire.mjs';

const builder = await createBuilder();

const weatherApi = await builder.addDotnetProject(
  'weatherapi',
  '../WeatherApi/WeatherApi.csproj'
);

const blazorApp = await builder
  .addBlazorWasmProject('app', '../MyBlazorApp/MyBlazorApp.csproj')
  .withReference(weatherApi);

await builder
  .addDotnetProjectBlazorGateway('gateway')
  .withExternalHttpEndpoints()
  .withBlazorClientApp(blazorApp);

await builder.build().run();
```

</TabItem>
<TabItem id='csharp' label='C#'>

```csharp title="AppHost.cs"
#pragma warning disable ASPIREBLAZOR001

var builder = DistributedApplication.CreateBuilder(args);

var weatherApi = builder.AddDotnetProject("weatherapi", "../WeatherApi/WeatherApi.csproj");

var blazorApp = builder.AddBlazorWasmApp("app", "../MyBlazorApp/MyBlazorApp.csproj")
    .WithReference(weatherApi);

builder.AddDotnetProjectBlazorGateway("gateway")
    .WithExternalHttpEndpoints()
    .WithBlazorClientApp(blazorApp);

builder.Build().Run();
```

</TabItem>
</Tabs>

The gateway forwards the client's service references to the browser app and is included when you publish the AppHost. Browser-debugger resources are created only for local runs.

<Aside type="note">
  When you reference API endpoints from a Blazor app resource, Aspire publishes
  service discovery connection properties to the consuming app. For details and
  examples, see [Connect Blazor apps and APIs](../blazor-connect/).
</Aside>

:::note
`Aspire.Hosting.Blazor` is a prerelease package, and its APIs may change in future releases. Experimental Blazor hosting types, such as `BlazorWasmAppResource`, report the [`ASPIREBLAZOR001`](/diagnostics/aspireblazor001/) diagnostic, so the C# examples suppress it.
:::
