This quickstart creates the same minimal application model in every AppHost language: one Redis resource named `cache`. The Aspire CLI generates the language SDK, starts Redis, and opens the same dashboard regardless of the syntax you choose.

:::note[Prerequisites]
Install the [Aspire prerequisites](/get-started/prerequisites/) and the [Aspire CLI](/get-started/install-cli/) before continuing. Experimental AppHost languages also require their feature flag and language toolchain.
:::

## Create the AppHost

<AppHostLanguagePivot id="typescript">

<Steps>

1. Create an empty TypeScript AppHost:

   ```bash title="Create a TypeScript AppHost"
   aspire new aspire-ts-empty -n aspire-app -o aspire-app
   ```

1. Change to the new directory:

   ```bash title="Change directories"
   cd aspire-app
   ```

## Add Redis

Run the same integration command from the AppHost directory:

```bash title="Add the Redis hosting integration"
aspire add redis
```

The CLI records `Aspire.Hosting.Redis` in the AppHost configuration and regenerates the language SDK with the Redis APIs.

## Define the application model

Replace the scaffolded AppHost entry point with the language-specific example.

<AppHostLanguagePivot id="typescript">

```typescript title="apphost.mts"
import { createBuilder } from './.aspire/modules/aspire.mjs';

const builder = await createBuilder();

const cache = await builder.addRedis('cache');

await builder.build().run();
```

TypeScript generated APIs are asynchronous and camel-cased. Await builder operations and the final `build().run()` chain.

</AppHostLanguagePivot>
<AppHostLanguagePivot id="csharp">

```csharp title="apphost.cs"
#:sdk Aspire.AppHost.Sdk@%ASPIRE_VERSION%
#:package Aspire.Hosting.Redis@%ASPIRE_VERSION%

var builder = DistributedApplication.CreateBuilder(args);

var cache = builder.AddRedis("cache");

builder.Build().Run();
```

C# hosting APIs use synchronous PascalCase fluent methods.

</AppHostLanguagePivot>
<AppHostLanguagePivot id="python">

```python title="apphost.py"
from aspire_app import create_builder

with create_builder() as builder:
    cache = builder.add_redis("cache")
    builder.run()
```

Python generated APIs use `snake_case`. The `create_builder()` context manager owns the connection to the host process and `builder.run()` builds and runs the model.

</AppHostLanguagePivot>
<AppHostLanguagePivot id="go">

```go title="apphost.go"
package main

import (
	"log"

	"apphost/modules/aspire"
)

func main() {
	builder, err := aspire.CreateBuilder()
	if err != nil {
		log.Fatal(aspire.FormatError(err))
	}

	cache := builder.AddRedis("cache")
	if err := cache.Err(); err != nil {
		log.Fatal(aspire.FormatError(err))
	}

	app, err := builder.Build()
	if err != nil {
		log.Fatal(aspire.FormatError(err))
	}
	if err := app.Run(); err != nil {
		log.Fatal(aspire.FormatError(err))
	}
}
```

Go fluent resource methods accumulate errors on the receiver. Check `Err()` after a chain, and format returned errors with `aspire.FormatError`.

</AppHostLanguagePivot>
<AppHostLanguagePivot id="java">

```java title="AppHost.java"
import aspire.*;

void main() throws Exception {
    var builder = DistributedApplication.CreateBuilder();

    var cache = builder.addRedis("cache");

    builder.build().run();
}
```

Java generated APIs use camelCase fluent methods. The scaffold targets JDK 25 so the compact source file can use an instance `main` method.

</AppHostLanguagePivot>
<AppHostLanguagePivot id="rust">

```rust title="apphost.rs"
#[path = ".aspire/modules/mod.rs"]
mod aspire;

use aspire::*;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let builder = create_builder(None)?;

    let cache = builder.add_redis("cache", None, None)?;

    let app = builder.build()?;
    app.run(None)?;
    Ok(())
}
```

Rust generated APIs use `snake_case` and return `Result`. Propagate AppHost errors with `?` or handle them explicitly.

</AppHostLanguagePivot>

## Run the app

<Steps>

1. Start the AppHost:

   ```bash title="Run the AppHost"
   aspire run
   ```

   Aspire restores the language SDK when needed, starts the guest AppHost and shared orchestration host, launches Redis, and prints the dashboard URL.

1. Open the dashboard URL from the terminal and confirm that the `cache` resource reaches the **Running** state.

1. Stop the AppHost by pressing <Kbd windows="Ctrl+C" mac="⌃+C" /> in the terminal.

</Steps>

## Template availability

The CLI currently provides these AppHost templates:

| AppHost language | Empty template ID                | Starter template                                                                                     |
| ---------------- | -------------------------------- | ---------------------------------------------------------------------------------------------------- |
| TypeScript       | `aspire-ts-empty`                | `aspire-ts-starter` (Express and React)                                                              |
| C#               | `aspire-empty --language csharp` | `aspire-starter`                                                                                     |
| Python           | `aspire-py-empty`                | No Python AppHost starter. `aspire-py-starter` uses a **TypeScript AppHost** with FastAPI and React. |
| Go               | `aspire-go-empty`                | `aspire-go-starter` (Go API and Redis)                                                               |
| Java             | `aspire-java-empty`              | `aspire-java-starter` (Spring Boot and React)                                                        |
| Rust             | `aspire-rust-empty`              | No starter template                                                                                  |
