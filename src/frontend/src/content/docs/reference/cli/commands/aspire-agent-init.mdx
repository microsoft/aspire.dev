## Name

`aspire agent init` - Initialize AI agent configuration for detected agent environments.

## Synopsis

```bash title="Aspire CLI"
aspire agent init [options]
```

## Description

The `aspire agent init` command edits the selected AI coding agents' settings files to enable plugins and skill catalogs. It can also install companion tools and configure the Aspire MCP server.

In interactive setup:

1. Select GitHub Copilot, Claude Code, or OpenCode. The CLI pre-selects detected agents, or GitHub Copilot if it detects none.
2. Select `aspire` and any companion tools you need.
3. Choose project scope for repo settings or global scope for user-level settings.

To configure the Aspire Model Context Protocol (MCP) server, opt in at the standalone setup prompt or pass `--mcp`. Setup chained from `aspire new` or `aspire init` skips MCP configuration.

<Aside type="note" title="Aspire workflow skills">
  With no `skillSources` setting, the CLI enables the `aspire` plugin from the
  [`microsoft/aspire-skills`](https://github.com/microsoft/aspire-skills)
  marketplace for GitHub Copilot and Claude Code, or adds the Aspire skill
  catalog to OpenCode's settings. Configuration can override or disable this
  built-in source. The Aspire CLI no longer ships an embedded skills bundle.
</Aside>

### Agent configuration files

For GitHub Copilot and Claude Code, the CLI adds marketplaces to `extraKnownMarketplaces` and enables their plugins in `enabledPlugins`. The built-in plugin is `aspire@aspire-skills`. For OpenCode, the CLI adds catalog URLs to the `skills` setting.

The default settings file locations are:

| Agent | Project scope | Global scope |
| ----- | ------------- | ------------ |
| GitHub Copilot | `.github/copilot/settings.json` | `~/.copilot/settings.json` |
| Claude Code | `.claude/settings.json` | `~/.claude/settings.json` |
| OpenCode | `opencode.jsonc` | `~/.config/opencode/opencode.jsonc` |

Client-specific directory overrides change the user-level paths. OpenCode reuses existing JSON or JSONC configuration files, including project files under `.opencode/`.

Each agent downloads and loads its configured plugins or skills. The CLI preserves existing local Aspire skill files and warns if they might override plugin-provided skills.

In a Copilot agent environment, the Aspire plugin also provides [canvas extensions](/get-started/aspire-skills/#copilot-canvas-extensions) for environment checks, AppHost resources, and wiring proposals.

### Skills and tools

The CLI selects `aspire` by default in standalone and chained setup. This choice applies every enabled [`skillSources`](/reference/cli/configuration/#configure-agent-plugins-and-skill-sources) entry. Set `skillSources.default.enabled` to `false` to configure other plugins or catalogs without adding the built-in Aspire source. Selecting `aspire` doesn't override that exclusion.

Select `playwright-cli` or `dotnet-inspect` separately for companion tools. The CLI offers `dotnet-inspect` only for applicable .NET AppHosts.

The Aspire plugin provides its workflow skills together. Select `aspire` rather than individual workflow IDs such as `aspireify`. Enabling the plugin doesn't run its workflows; review and approve migration or AppHost-wiring changes before the agent applies them.

## Options

The following options are available:

- **`--workspace-root <workspace-root>`**

  Path to the workspace root directory. When not specified, the current directory is used as the workspace root.

- **`--agents <agents>`**

  Comma-separated agent IDs: `copilot`, `claude`, or `opencode`. Use `all` for every supported agent or `none` to skip agent configuration. By default, the CLI selects detected agents, or GitHub Copilot if it detects none.

- **`--scope <project|global>`**

  Write agent settings and companion skill files at project or user scope. Interactive setup prompts for a scope; non-interactive setup defaults to `project`.

- **`--skills <skills>`**

  Comma-separated choices: `aspire`, `playwright-cli`, or `dotnet-inspect`. Use `all` for every applicable choice or `none` to skip them. Defaults to `aspire`, which applies all enabled skill sources. MCP setup is separate.

- **`--mcp`**

  Configure the Aspire MCP server for the selected agents. Non-interactive setup skips MCP unless you pass this option.

## Examples

- Initialize AI agent configuration for detected agent environments:

  ```bash title="Aspire CLI"
  aspire agent init
  ```

- Enable skill sources for GitHub Copilot at project scope:

  ```bash title="Aspire CLI"
  aspire agent init --agents copilot --skills aspire --scope project --non-interactive
  ```

- Configure all supported agents and applicable companion tools at global scope:

  ```bash title="Aspire CLI"
  aspire agent init --agents all --skills all --scope global --non-interactive
  ```

- Initialize agent configuration from a specific workspace root:

  ```bash title="Aspire CLI"
  aspire agent init --workspace-root ./src
  ```
