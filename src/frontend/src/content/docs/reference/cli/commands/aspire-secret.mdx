## Name

`aspire secret` - Manage AppHost secrets.

## Synopsis

```bash title="Aspire CLI"
aspire secret [command] [options]
```

## Description

The `aspire secret` command manages secrets for an Aspire AppHost project. Secrets provide a safe way to store sensitive configuration values—such as passwords, API keys, and connection strings—outside of your project files.

Aspire uses secrets to persist values that resources need across restarts, such as auto-generated passwords for database containers. When you add a persistent resource that requires a password, Aspire saves the generated password. On subsequent runs, the saved password is reused so that the resource retains its state.

### Environment-specific secrets

Each `aspire secret` subcommand accepts `--environment` (or `-e`) to select the AppHost environment whose secrets you manage. Environment names are case-insensitive, and the default is `Development`. Secrets for each environment are stored in a separate JSON file in your user profile:

```text title="Secrets file location"
~/.aspire/secrets/<apphost-id>/<environment>.json
```

The `<apphost-id>` is the AppHost's `UserSecretsId` when it has one; otherwise, Aspire derives an ID from the AppHost file path. Use [`aspire secret path`](../aspire-secret-path/) to print the exact file for an environment.

When the AppHost runs, it loads the secrets file for its environment—for example, `Development` for `aspire run`, or `Production` for `aspire publish`, `aspire deploy`, and `aspire do` unless you pass a different `--environment`. Values that a deployment prompts for are saved to the same file. Secrets override `appsettings.json` values, while environment variables and command-line arguments still take precedence.

:::note[Upgrading to Aspire 17?]
The first time the `Development` environment is used, Aspire imports existing .NET user secrets into `Development.json` if that file doesn't exist. After that, `aspire secret` reads and writes only the Aspire secrets file. Set secrets for other environments with `--environment`.
:::

## Commands

The following commands are available:

| Command                                                        | Function                      |
| -------------------------------------------------------------- | ----------------------------- |
| [`aspire secret set <key> <value>`](../aspire-secret-set/)     | Set a secret value.           |
| [`aspire secret get <key>`](../aspire-secret-get/)             | Get a secret value.           |
| [`aspire secret list`](../aspire-secret-list/)                 | List all secrets.             |
| [`aspire secret delete <key>`](../aspire-secret-delete/)       | Delete a secret.              |
| [`aspire secret path`](../aspire-secret-path/)                 | Show the secrets file path.   |

## Examples

- Set a secret value for the current AppHost:

  ```bash title="Aspire CLI"
  aspire secret set Parameters:postgres-password MySecretPassword123
  ```

- Set a secret for the `Production` environment from an environment variable:

  ```bash title="Aspire CLI"
  aspire secret set Parameters:postgres-password --environment Production --envvar POSTGRES_PASSWORD
  ```

- List all secrets for a specific AppHost:

  ```bash title="Aspire CLI"
  aspire secret list --apphost ./src/MyApp.AppHost/MyApp.AppHost.csproj
  ```

- Get the value of a specific secret:

  ```bash title="Aspire CLI"
  aspire secret get Parameters:postgres-password
  ```

- Show the path to the secrets file:

  ```bash title="Aspire CLI"
  aspire secret path
  ```
